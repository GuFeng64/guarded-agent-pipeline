## 二、系统架构

### 2.1 Agent 清单

| # | Agent | 类型 | 职责 | 可见输入（隔离） |
|---|---|---|---|---|
| A1 | 采集 Agent | 诊断 + 工具调用 | 视图完整性/饱和/SNR/散射诊断；建议重采 | 4 视图原始谱 |
| A2a-e | **分支 Agents（5 个，并行）** | 模型推理 | b1 / CNN / b7 / b8 / b9 各自预测 | 各自视图 + 各自模型 |
| A3 | 汇总 Agent | 融合 | 等权融合 + 逐目标仿射 + σ；TS 结构性闭合 | 5 个分支的输出 |
| A4 | 评估 Agent | 规则 | σ → 可靠性分位；保形分位数 → 区间；按 RPD 分级 | ŷ + σ（**不含真值**） |
| A5 | 路由 Agent | **规划（核心智能）** | 预算约束下选择复测子集 | 区间 + 容许限（**不含真值**） |
| A6 | 报告 Agent | **模板 + LLM 改写措辞**（已接入并评估） | 结构化报告 | A5 的决策（**不含真值**） |
| A7 | 回流 Agent | 规则 | 标记高价值样本（设计，未验证） | 决策 + 真值（需人工确认后） |
| V | 校验器 | 审计 | 报告合规性检查 | 报告 + 真值（**唯一可见真值处**） |

**⭐⭐ 隔离的实现（已落地 `context.py`）：**

| 机制 | 做法 |
|---|---|
| 白名单 | `AGENT_ACCESS` 显式列出每个 Agent 可访问的键 |
| 越权拦截 | `GuardedView.__getitem__ / get / __contains__` 一律抛 `ContextViolation` |
| 只读 | `__setitem__ / update / pop` 抛 `ContextReadOnly` |
| 配置自检 | `for_agent()` 发券时**断言**白名单不含真值键（防止配置写错） |

**⭐ 已由自测抓出一个真实缺陷：`feedback` 最初被允许访问 `reference_values`（真值），
已改为只接收 validator 确认过的样本 ID。**

### ⭐⭐⭐ A3 的离线/在线分离（补齐真正的信任边界）

**问题**：进程隔离只覆盖了最不敏感的两个组件（报告渲染、RPD 分级），
而**真正必须用真值的 A3 融合系数拟合**仍在父进程。

**拆分后**
```python
fit_aggregator(...)            # 离线：拟合 base_coef / sig_coef / alpha / ash（用 Y+cow）
apply_aggregator_idx(fit, ...) # 在线：只读系数与分支预测，**不接触 Y**
```
**AggFit** 只含纯 numpy 系数（`base_coef / sig_coef / alpha / ash`），
不含与 Y 同形状的字段（自测断言）。

**结果**：闭合前 gap 0.0329 ｜ 闭合后 **0.0324** ｜ 新旧接口一致 ｜ apply 不引用 Y

**⚠️ α 对实现细节敏感**：内层重拟合 ⇒ α=[0.8,0.8,0.8,0.9,0.9]；
step481 不重拟合 ⇒ α=[0.8,0.8,0.8,0.95,0.9]；**两者 gap 都是 0.0324**
⇒ α 在 0.8–0.95 是平台。

**⭐⭐ 隔离的准确表述（经静态检查后更正）**

```
在线路径（intervals / plan / build / render / select）—— **完全不接触真值**
离线校准与评估（calibrate / metrics / coverage / cost）—— **允许使用真值，
  但必须以显式参数传入，不得作为类的常驻状态**
校验器 —— 唯一在校验流程中读取真值的模块
```

> ⚠️ 早期表述"评估 Agent 不含真值"不准确：
> 保形校准与 RPD 指标计算**必须**用真值，但它们在独立函数中完成，
> 且**在线路径**（`intervals` / `plan`）本身零接触。
> 判据由 `check_isolation.py` 按**函数级**静态检查保证。

**⭐ 上下文隔离的硬理由**：真值只在校验器可见。
否则"评估 Agent 判断可靠性"不再是盲的，第四章的全部结论都会被质疑为泄漏。

### 2.1.1 分支 Agent 的接口约定（T1.1 落地）

> ⚠️ 两个容易被误判的语义，都已在实现中固化并有自测保护。

| 项 | 约定 | 踩过的坑 |
|---|---|---|
| **单位** | 缓存中的分支预测**已是归一化空间**（相对该折 mu/sd） | 误当原始单位 ⇒ 再除一次 mu/sd ⇒ 双重归一化 ⇒ gap 0.0413 |
| **折结构** | 融合的仿射在**每折训练行**上单独拟合，使用该折的**内层预测 `f{fi}_*_tr`** | 只用全局 OOF ⇒ 训练行的预测来自别的折模型 ⇒ gap 错 |

**因此分支 Agent 必须提供三个并列接口：**
```python
agent.fold_train(fi) -> (m_tr, nt)   # 该折训练行的内层预测（融合拟合用）
agent.fold_test(fi)  -> (m_te, nt)   # 该折测试行的预测（OOF）
agent.oof(n, nt)     -> (n, nt)      # 全局 OOF（仅用于评估/报告）
```

**⭐ 数值锚点（自测断言）：**
```
等权三族融合  gap = 0.0329     ← 不含 TS 结构性闭合
v39 定稿      gap = 0.0324     ← 再叠加 TS 闭合（由 a3_aggregate 施加）
```

`

   └─ 分支级（5 个 Agent，⭐ 本系统的多 Agent 并行）

**⭐ 多 Agent 并行调度（分支级）**

| 项 | 设计 |
|---|---|
| 并行实体 | 5 个分支 Agent（b1 / CNN / b7 / b8 / b9） |
| 并行理由 | 计算特性迥异（57K PyTorch vs TabPFN 在上下文推理），天然独立无共享状态 |
| 超时处理 | 每路独立超时；失败返回结构化原因（禁止静默降级） |
| 归并顺序 | **按分支 ID 排序，不按完成时间**（保证确定性，章程规则 C2） |
| 降级决策 | 依据实测退化表三档（§三） |
| 观测 | 记录每分支耗时、成功/失败、是否降级 |

**⭐⭐ 分支级并行的真实价值（实测更正见 §2.3.1）**

`
· 5 个分支的预测可完全独立计算 ⇒ 并发有真实吞吐收益
· 失败是**真实的可能事件**（TabPFN 在上下文推理对显存/时延敏感）
· 且退化后果**已实测**（见 §三 退化表）⇒ 容错决策有依据
`

**⭐⭐ 调度实现（已落地 `orchestrator.py`）**

| 机制 | 做法 |
|---|---|
| 并发 | `ThreadPoolExecutor`，分支间并行 |
| 归并确定性 | **先全部 submit，再按 `CANONICAL_BRANCHES` 顺序逐个 `result(timeout)`** |
| 超时 | 每分支独立超时；`cancel()` 后返回 `BranchResult(ok=False, error='timeout')` |
| 异常 | 抓成 `error='exception'`，不抛到上层 |
| 族级保护 | TabPFN 三变体全缺 ⇒ `RuntimeError`（退化 +0.0258，不可降级） |
| 可观测性 | 每分支 `elapsed`、编排日志 `orch.log` |

**⭐⭐⭐ 已有判据（7 项自测全通过）**
```
① 并行结果 ≡ 串行结果（逐元素相等）
② 归并顺序 = 规范顺序（与完成时间无关）
③ 超时结构化  ④ 降级标志/缺失列表正确
⑤ 整族缺失不可降级  ⑥ 异常不逃逸  ⑦ 未知分支名报错
```

**⚠️ 已知限制**：超时后 `cancel()` 对已在运行的线程无效（Python 线程无法强杀）
⇒ 超时只保证"不阻塞编排"，不保证资源立即释放。


## 四、⭐ 路由 Agent 的规划能力（第四章的落地）

### 4.1 为什么它是"真 Agent"而不是 if/else

```
❌ 函数版：if σ > τ then 复测
✅ 规划版：给定 K 个复测预算，结合**区间位置 × 决策阈值 × 错判代价**选择复测子集
```

**⭐⭐ 关键前提（已验证）：规划产生优势的唯一条件是"决策有阈值"**

```
若决策无阈值（只看误差）⇒ 复测最宽区间即可 ⇒ 退化为按 σ 排序，规划无优势
若决策有档位阈值（如 Fat ≥3.5% 进溢价档）
   ⇒ 区间**跨越阈值**的样本错判代价高，最值得复测
   ⇒ 区间宽但远离阈值的样本，错判代价低
```

### 4.1.1 规划信号：从 v1 到 v2

| 版本 | 信号 | 问题 |
|---|---|---|
| v1 | 区间是否跨越阈值（0/1 + 靠近程度） | 跨 1 档与跨 3 档被同等对待 ⇒ Fat 上差 oracle 5 倍 |
| **v2（采用）** | **期望档位误差**：把区间按阈值切段，`E[Δgrade] = Σ_k P(段_k)·|grade(段_k) − grade(ŷ)|` | —— |

**⭐⭐ v2 是对保形区间做概率推理，不是阈值判断 —— 这是 Agent 能力而非规则。**

### 4.2 已验证结果（P3-core）

| 目标 | 预算 | random | greedy_s | `plan_expected`（v3） | oracle | v2 vs greedy |
|---|---|---|---|---|---|---|
| Fat | 20% | 349 | 399 | 299 | 59 | **25.1%** |
| Fat | 40% | 339 | 349 | 179 | 119 | **48.7%** |
| Prot | 20% | 129 | 139 | 59 | 59 | **57.6%**（=oracle） |
| TS | 20% | 259 | 259 | 89 | 59 | **65.6%** |

**三个关键发现：**
```
① 规划显著优于按 σ 拒识（25%–66%）
② **greedy_s 有时比 random 还差**（Prot 20%: 139 vs 129）
   ⇒ 按 σ 排序 ≠ 按代价排序（章程规则 F3）
③ 与 oracle 的差距是**不可约成本**，不是启发式缺陷（见 4.2.1）
```

### 4.1.2 已实现的算法（`agents/a5_route.py` v3）—— **损失函数无关**

**统一框架**
```python
E[L_i] = ∫ L(ŷ_i, y) · p_i(y) dy        # p_i(y) 由保形区间 + σ 构造
按 E[L_i] 降序复测                       # 对任意损失 L 都是最优排序
```

**四种可插拔损失（前三种对应真实结构）**

| loss | 来源 | 定义 |
|---|---|---|
| `linear` | ✅ 真实按质论价（奶业协会） | `w·\|y−ŷ\|`，w 为脂肪/蛋白单价 |
| `grade` | 企业分级（**固定阈值，与数据无关**） | `1[档位不同]` |
| `compliance` | ✅ 真实国标 GB 19645/25190 | `10·1[y < 限值]`（不对称） |

**实测（自测断言）**

| loss | 结果 |
|---|---|
| **linear** | plan 与 greedy_σ **完全相等（0.0%）** ⇒ 数学等价、无损 |
| **grade** | plan 优 **+5.0% ~ +8.3%** |
| **compliance** | Fat 优 **+17.5% / +28.1%**；Prot 为空检验（0/297 不达标） |

**⭐⭐ 为什么线性下等价：** `L=|y−ŷ|` 且 `y~U[ŷ−w,ŷ+w]` ⇒ `E[L]=w/2 ∝ σ`
⇒ 排序相同。**这是保证而非缺陷：统一框架在线性下不会更差。**

**⭐⭐⭐ 不达标样本核查（决定哪些情景有意义）**
```
Fat 1.71–7.70，国标 3.1 ⇒ 17/297 不达标 ⇒ 合规情景有意义
Prot 2.99–5.07，国标 2.9 ⇒ 0/297 不达标 ⇒ 合规情景为空检验
非脂乳固体 8.53–11.11，国标 8.1 ⇒ 0/297 不达标
⇒ 本数据是**研究级优质牛群**，系统价值在**精细化定价**而非合规筛查
```

**⚠️ 试过但未采纳（均 <1.5%，在噪声内）**
```
距离代理预测 |error|：knnk +0.26 ｜ mahal +0.23 ｜ knn1 +0.10 ｜ margin −0.16
  而 σ = +0.28 ⇒ 距离代理不如 σ
元模型（σ+|ŷ|+距离 → 岭回归）：线性损失下仅 +0.3~1.1%
⇒ **线性损失下 σ 排序已近可达上限；与 oracle 的 11% 差距是信息上限**
```

### 4.1.6 ⭐⭐⭐ Guarded Agent：LLM 提议 + Tool Use + 门控

**为什么是这个架构（由实测推导，不是为简历加功能）**
```
LLM 单独决策准确率 46.7%（CI 35.8–57.8%）⇒ 不能直接决策
但也不该完全弃用：它能整合"区间宽度 + 阈值距离 + 退化状态"多线索
⇒ **LLM 提议 + 确定性门控**
```

**架构**：LLM 通过 5 个只读工具主动查询（`get_interval` / `get_grade` /
`get_thresholds` / `get_regret` / `get_status`），提出决策 + 理由码；
**7 条门控规则**逐条校验（每条都可用阴性对照推翻），
不通过则**回退规则决策**。

**实测（12 样本）**
| 指标 | 结果 |
|---|---|
| 门控采纳率 | **100%** |
| 工具调用 | **18 次/样本**（14–19） |
| 决策与规则一致 | 11/12 |
| 真实损失 Δ | **−0.00208**（1 优 0 劣，不显著） |

**🔴 由实测暴露并修掉的两个缺陷**
```
① G5 白名单漏 `width = hi − lo`（工具明确返回它）
   ⇒ LLM 正确引用区间宽度反被判不可溯源 ⇒ **门控 100% 拒绝、Agent 成空壳**
   ⭐ 原则：白名单 = 工具能告诉 LLM 的全部量
② regret 写成 `q·σ`，而实测半宽 = **q（绝对量）**，差 14 倍
```

### 4.1.3 ⭐⭐⭐ 多 Agent 交互（agent-as-tool + 审议环）

**此前审计结论：不是多 Agent 系统**
```
MAS 五条判据：① 多个自主 Agent ② Agent 间通信 ③ 协商/协调
              ④ 去中心化控制 ⑤ 涌现行为
⇒ 此前全部不满足：只有 1 个 Agent 有自主性、无通信、中心化编排
```

**升级 ①：agent-as-tool（能力边界不同）**
```
A5b 决策 Agent ⇄ A1 感知 Agent
   A5b **看不到光谱**；A1 **能看光谱但不能决策**
   ⇒ 决策 Agent 必须调 `request_spectral_recheck` 请求 A1
   ⇒ 这是**跨 Agent 请求**，不是查数据
```

**升级 ②：审议环（proposer–critic）**
```
A5b 提议 → V 质疑（带可执行建议）→ A5b 修订 → 再审（≤3 轮）
仍不通过 ⇒ 回退规则
```

**实测（真实 LLM）**

| 场景 | 结果 |
|---|---|
| 正常样本 ×8 | A1 被调用 **2/8** ✅；工具 19.5 次/样本；修订 0（首轮合规） |
| **S1 整族缺失去退化** | round 1 违规 G3 ⇒ **round 2 修订通过**（2/2） |
| **S3 退化 + G6** | **rounds=3, revisions=2**：G3+G6(TS) → G3+G6(Fat,Prot) → 通过 |

**⚠️ 诚实边界**：正常样本下审议环很少触发（LLM 首轮通常合规）
⇒ 它是**安全网**，不是常规路径。

### 4.1.4 ⭐⭐ G7 预算门控（批量级）

**为什么逐样本门控不够**
```
A5 路由 = **批量**决策（预算 B）；Guarded Agent = **逐样本**决策
⇒ 逐样本都合法、但整体违反预算的提议集合，**不可执行**
```

**G7 逻辑**
```
① 逐样本过 G1–G6
② 统计"通过且由 LLM 给出"的 retest 数
③ 超预算 ⇒ 按期望损失降序保留前 k，其余**回退规则**
```

**自测**：10 样本全 retest、预算 2 ⇒ 最终 retest **2**、回退规则 **8** ✅

**接入**：`PipelineConfig(decision_mode='guarded')`；默认 `'rule'` 行为不变。
逐目标动作归约成样本级决策（任一 retest ⇒ retest；全 reference ⇒ reference）。

### 4.1.7 ⭐⭐ 可靠性指标的实现（模块化 + 解析值自检）

**为什么抽成模块**：本项目已在"排序方向"上犯错 **4 次**，
if 每个分析脚本各自实现 AURC，错误就会各自复发。

```
reliability_metrics.py
  · aurc(score, err)                   —— 升序保留，risk=保留集均值，∫risk dc
  · risk_at_budget(score, err, b)      —— 拒识 b 后的保留集均值
  · worse_first(score)                 —— **具名**方向（章程 C43）
  · spearman_abs_err / kendall_abs_err
```

**自检用解析值（决定性阴性对照）**
| 情形 | 解析值 | 实测 |
|---|---|---|
| score = err（完美排序） | **1.60** | 1.600000 ✅ |
| score = −err（完全反序） | **3.20** | 3.200000 ✅ |
| n=200 oracle / random / 反序 | 递增 | 0.3459 / 0.7708 / 1.3055 ✅ |
| Spearman 端点 | ±1.0 | +1.0000 / −1.0000 ✅ |

**⚠️ 4 次方向错误的清单**
```
① AURC 算成"被拒样本"的平均误差
② 同处修正不彻底
③ step526 C 段 order 升序当降序用 ⇒ 与 AURC 自相矛盾
④ 自检里把解析值写成 2.0/4.0（那是"风险的简单平均"，
   而 AURC 是对覆盖率**积分**），且预算方向期望写反
```

### 4.1.3 早期版本（v2，已被 v3 取代）

```python
E[Δgrade]_{i,t} = Σ_k P(段_k) · |grade(段_k) − grade(ŷ_i)|
   其中区间 [ŷ−q, ŷ+q] 按决策阈值切片，P(段_k) = 段长 / 区间长

sample_score_i = Σ_{t ∈ 可报告目标} C_ERR · E[Δgrade]_{i,t}
    ⚠️ 只累加**可报告目标**（Fat/Prot/TS）；Lact/Urea 的 E 恒为 0

预算 K 内按 sample_score 降序复测
```

**⭐ 关于"三分法"的澄清**

> 早期设计的"已通过 / 可修 / 无望"三分法是**叙述性表述**，
> 已被验证后的实现取代：在"固定预算 K 且复测可完全修正档位"的模型下，
> 最优策略就是**按期望档位误差排序取前 K**，不需要额外的"无望"分支。

**⭐⭐ 决策门结果（P3 已通过）**

### 4.2.1 ⭐⭐⭐ 最优性刻画：v2 已达可实现上界

**上界的定义（不是 oracle）：**
```
oracle 需知道真值 ⇒ 不可实现
可实现上界 = 仅知 ŷ 与全局误差尺度时的信息论最优
           y ~ N(ŷ, RMSE_global) ⇒ P(档位错判) 解析可算
           ⭐ 本数据误差近似同方差 ⇒ 这就是可达上限
```

| 目标 | 预算 | **v2** | **homo_opt（上界）** | oracle | v2 vs 上界 |
|---|---|---|---|---|---|
| Fat | 20% | **299** | 289 | 59 | −3.5% |
| Fat | 30% | **229** | 239 | 89 | **+4.2%**（更优） |
| **Prot** | 20/30/40% | **59/89/119** | 59/89/119 | 59/89/119 | **0.0%（且 = oracle）** |
| **TS** | 10–40% | **89–129** | 完全相同 | 59–119 | **0.0%** |

**结论：**
```
· Prot：v2 = 上界 = oracle ⇒ **完全最优**
· TS  ：v2 = 上界 ⇒ 与 oracle 的差距**不可约**
· Fat ：v2 ≈ 上界（±5%）
⇒ **算法已定型，停止迭代**（v3 σ 调制 / v4 高斯近似 / v5 混合权重全部无效）
```

**⭐ 为什么 σ 类改进无效（与模型侧自洽）：**
```

⇒ 常数宽度区间 + 阈值邻近度已是全部可用信息
```

## 四之二、报告与校验的实现（P4）

### 报告 Agent（`agents/a6_report.py`）

**⭐⭐ 核心架构：LLM 在结构上无法改数值**

```
LLM 只能改写**外层叙述模板**：{sample_id} / {verdict} / {lines} / {note}
单个目标的数值在 LINE_TEMPLATE 中，由代码用 .format 填入
⇒ 模板层无法篡改数值；唯一风险是"对最终文本后处理" ⇒ 用 verify_numbers() 兜底
```

**两个设计细节：**
```
① 不可报告目标（Lact/Urea）**不给出数值**，只声明"不可用，请转参考方法"
② 降级结果必须在报告中写明缺失分支
```

### ⭐ LLM 叙述层（`agents/a6_llm.py`）—— 已接入并评估

**接入方式**
```
LLM 只接收**带占位符的结构化模板**（{sample_id}/{verdict}/{lines}/{note}），
返回**仍带占位符的叙述模板**；数值由代码 .format 填入
⇒ LLM 在结构上无法编造或改动数值
```

**安全约定**
```
密钥只从环境变量 `LLM_API_KEY` 读取，**绝不写入任何文件**
无密钥 / 网络失败 / 占位符丢失 ⇒ 自动回退到确定性默认模板（系统仍完整可用）
```

| 指标 | 结果 |
|---|---|
| 占位符保留 | **3/3 次调用成功**（4 个必需占位符全保留） |
| 稳定性 | **1 个不同模板 / 3 次调用**（完全一致） |
| 成本 | 延迟 **0.96 s** ｜ **206 tokens** ｜ **O(1)**（改一次、复用 297 样本） |

**⭐ 可写进论文的表述**
> "LLM 仅改写报告模板的措辞，不参与任何数值生成；
> 在 297 个样本上报告数值与结构化输出的一致率为 100%（0 例被改动）；
> 模板改写仅需 1 次调用（0.96 s，206 tokens），成本与样本量无关。"

### ⭐⭐ LLM 推理层（`agents/a6_llm_reason.py`）—— 已评估，**结论是不用于决策**

**设计动机**：模板润色无信息增量。故让 LLM 做模板做不到的事：
读区间与阈值，判断跨越情况、给建议、给理由。

**输出契约（受约束，便于自动校验与消融）**
```json
{"crossed": [...], "recommendation": "report|retest|reference",
 "concepts": ["THRESHOLD_CROSS" | "WIDE_INTERVAL" | "HIGH_SIGMA" | "DEGRADED"],
 "reason": "一句中文理由"}
```

**文献依据**
- [Right Answer, Wrong Reason (IEEE 2026)](https://ieeexplore.ieee.org/document/11710560)：
  正确率 ≠ 忠实性，提出 ESI / CFS / PSS 三指标
- [The Validity–Fidelity Gap (2026)](https://aclanthology.org/2026.findings-aacl.107/)：
  JSON 可解析 ≠ 内容正确（representation drift）
- [ChemBench (ACL 2026 Findings)](https://aclanthology.org/2026.findings-acl.2015/)：
  分析化学场景的 LLM 基准

**评估结果（`evaluate_llm.py`，日志 `logs/agent_llm_eval2.txt`）**

| 指标 | 结果 | 判读 |
|---|---|---|
| **① 阈值跨越判断准确率** | **55.6%**（n=18） | 🔴 LLM 的数值比较**不可靠** |
| 建议与参考规则一致率 | 66.7%（n=18） | ⚠️ 约 2/3 |
| **② ESI 重复一致性** | 88.9% | ✓ 较稳 |
| **③ CFS 概念消融翻转率** | **1/29 = 3.4%** | 🔴🔴 引用的理由**基本不驱动决策** |
| **④ PSS 改写一致性** | 83.3% | ⚠️ 对措辞敏感 |
| ⑤ 契约遵守（字段合法） | **100%**（18/18） | ✓ 格式可靠 |
| ⑥ 成本 | 101 次调用 / 25,645 tokens / 1.16 s 每次 | — |

**⭐⭐⭐ 由此得出的设计决策（有实验依据，而非出于保守）**

> "我们按 IEEE 2026 的忠实性框架评估了 LLM 推理层：阈值跨越判断准确率仅 55.6%，
> 概念消融翻转率仅 3.4%（表明其给出的理由是事后合理化），改写稳健性 83.3%。
> 因此**有意将 LLM 限制在报告措辞层**，所有数值与决策保持确定性。"

**代价与收益**
```
代价：报告措辞缺乏灵活性
收益：数值可信度 100%（297/297 一致）、可复现、可审计
⭐ 契约遵守 100% 说明 LLM 可被安全约束在表述层
```

### ⭐⭐ 数值溯源校验（`verify_numbers_strict`）—— 防编造

**为什么需要**：原 `verify_numbers` 只检查"该出现的数值在不在"，
实测**无法检出** LLM 新增的数字（如"误差约 0.8765"）。

**白名单法**
```
抽取文本中所有数字 → 逐个溯源：
  · 结构化报告内数值（**仅模板实际格式**：值/区间/R² 用 4 位，RPD 用 2 位）
  · 区间水平（整数百分比）
  · 样本编号数字（原样串）
任一数字无法溯源 ⇒ 违规
```

| 输入 | 修复前 | 修复后 |
|---|---|---|
| 正常文本 | ✅ | ✅ |
| 编造 `0.8765` | 🔴 漏检 | ✅ 检出 |
| 编造 `12.3` | 🔴 漏检 | ✅ 检出 |
| 编造 `7.5` | 🔴 漏检 | ✅ 检出 |

**⭐ 关键设计**：白名单只能含**模板实际使用的格式**。
若含全部舍入变体，则 `12.3456` 会让 `'12.3'` 也合法 ⇒ 白名单过宽。

### 为什么删掉了散射与基线检查

| 异常 | 是否被 SNV 消除 | 处理 |
|---|---|---|
| 乘性散射 `a·x` | ✅ `snv(a·x)=snv(x)`，距离 **0.0000** | 不检查 |
| 加性偏移 `x+b` | ✅ `snv(x+b)=snv(x)`（减均值），距离 **0.0000** | 不检查 |
| 波长依赖斜率 | 部分（距离 0.08，gap 变化在噪声内） | 不检查 |
| **毛刺/尖峰** | ❌ 距离 **0.61**，gap **+1.38（灾难性）** | **必检 + 修复** |

**⭐ 教训**：管线所有视图都做 SNV，而 SNV 对前两类异常数学上免疫
⇒ 在 SNV 之前检查它们，检出的"异常"根本不会传入模型。（对应章程规则 B9）

### 尖峰指标（经实测校准，**不能自归一化**）

```
spike_index = max|x − smooth| / std(x)        ← 相对谱自身尺度
```

|---|---|

| 修复后 | 0.28 – 0.50 |

**双阈值**：`soft=0.10` 检出（干净 0/297 假阳性）；`hard=1.0` 判"修复后可否接受"
