## P3-core ⭐ 路由规划核心智能的前置验证（✅ 已完成）

> **为什么放在最前**：若规划不能胜过"贪心按 σ"，第五章架构不成立。
> 这必须先用缓存预测验证，而不是先搭基础设施（章程规则 Z4）。

### 关键洞察（决定成败）

```
若"复测"=拿到参考法真值 ⇒ 所有被复测样本都变可报告
⇒ 最优策略 = 复测区间最宽的 = 贪心按 σ
⇒ **规划没有优势**

⭐⭐ 规划产生优势的唯一条件：**决策有阈值**（如 Fat ≥3.5% 进溢价档）
   ⇒ 区间**跨越阈值**的样本，错判代价高，最值得复测
   ⇒ 区间宽但远离阈值的样本，错判代价低
```

### 结果（step507 / step508，模拟阈值 + 模拟代价）

**v1（是否跨越阈值）vs greedy（按 σ）：**

| 目标 | 预算 | random | greedy_s | plan_v1 | plan vs greedy |
|---|---|---|---|---|---|
| Fat | 20% | 349 | 399 | 319 | **20.1%** |
| Fat | 40% | 339 | 349 | 219 | **37.2%** |
| Prot | 20% | 129 | 139 | 59 | **57.6%** |
| TS | 20% | 259 | 259 | 89 | **65.6%** |

**v2（期望档位误差，对区间做概率推理）进一步改善 Fat：**

| 预算 | greedy_s | plan_v1 | **`plan_expected`（v3）** | oracle | v2 vs greedy |
|---|---|---|---|---|---|
| 10% | 400 | 390 | **330** | 150 | 17.5% |
| 20% | 399 | 319 | **299** | 59 | 25.1% |
| 30% | 359 | 279 | **239** | 89 | 33.4% |
| 40% | 349 | 219 | **179** | 119 | 48.7% |

**Pro / TS 上 v1 已达到 oracle**（59/89/119 与 oracle 相同）。

### 三个必须记录的发现

```
① **规划显著优于按 σ 拒识**（17%–66%）⇒ 核心智能成立
② **greedy_s 有时比 random 还差**（Prot 20%: 139 vs 129）
   ⇒ 按 σ 排序与"按决策代价"不一致 —— σ 适合排序难度，不适合排序代价
③ **Fat 上 v2 仍远不如 oracle**（20%: 299 vs 59，差 5 倍）
   ⇒ 启发式还有明确改进空间（不是"已最优"）
```

### 迭代记录 1：v3 / v4 / v5 尝试把 σ 引入代价推理（均无改善）

| 版本 | 做法 | 结果 |
|---|---|---|
| v3 | σ 调制区间宽度后再切片 | Fat 20% 269（v2 299）但 30% 反而 239（v2 229）⇒ 不稳定 |
| v4 | 高斯近似 `y~N(ŷ, (q/1.645)·σ̃)` 对档位带积分 | 与 v3 几乎相同 |
| v5 | `E[Δgrade] + λ·σ̃`，λ 内层选（Fat λ=1.0, Prot λ=0, TS λ=1.0） | 仅零散改善，无一致优势 |

**⭐ 结论：σ 不能带来额外信息。原因已由模型侧实测确定：**
```
误差**近似同方差**（σ 归一化使保形区间反而宽 16–23%）
⇒ 保形区间已是常数宽度，阈值邻近度就是全部可用信息
⇒ 与模型章程规则 CE「排序可靠性 ≠ 刻画不确定性幅度」自洽
```

### 迭代记录 2 ⭐⭐⭐：oracle 不是合适的对照，改用"可实现上界"

**问题：**
```
Fat 20% 预算下 oracle 代价 = K·C_TEST = 59
⇒ 说明 oracle 把所有档位错误样本都修好了
⇒ 但它需要**知道真值** ⇒ 不可实现 ⇒ 无法判断我们离"可达到的最好"有多近
```

**定义可实现上界（homoscedastic-optimal）：**
```
仅知 ŷ 与全局误差尺度 RMSE 时，最优规则 = 按 P(档位错判) 降序复测
    y ~ N(ŷ, RMSE_global) ⇒ P(错判) 可解析计算
⭐ 这是"信息论最优"，本数据误差近似同方差 ⇒ 它就是可达上限
```

**结果：**

| 目标 | 预算 | random | sigma | **v2** | **homo_opt** | oracle | v2 vs homo |
|---|---|---|---|---|---|---|---|
| Fat | 10% | 390 | 400 | **330** | 330 | 150 | **0.0%** |
| Fat | 20% | 349 | 399 | **299** | 289 | 59 | −3.5% |
| Fat | 30% | 359 | 359 | **229** | 239 | 89 | **+4.2%**（v2 更优） |
| Fat | 40% | 339 | 349 | **199** | 189 | 119 | −5.3% |
| **Prot** | 20/30/40% | 129/139/169 | 139/159/189 | **59/89/119** | 59/89/119 | 59/89/119 | **0.0%（且 = oracle）** |
| **TS** | 10–40% | 229–249 | 240–289 | **89–129** | **完全相同** | 59–119 | **0.0%** |

**⭐⭐⭐ 三个结论：**

```
① **v2 已接近甚至达到信息论最优**
   Prot：v2 = homo_opt = **oracle**（完全最优）
   TS  ：v2 = homo_opt（与 oracle 的差距不可约）
   Fat ：v2 ≈ homo_opt（±5%）
② 先前担心的"Fat 差 oracle 5 倍"是**误解**：
   oracle 需要知道真值，其差距是**不可约的"不知道真值"成本**
③ v3/v4/v5 无改善，因误差近似同方差 ⇒ σ 无额外信息
```

**⇒ 路由规划的核心智能已定型：``plan_expected`（v3）`（常数区间 + 期望档位误差），不再迭代。**

### ⚠️ 结论的适用边界（必须写进论文）

```
决策阈值（Fat 3.0/3.5/4.0/4.5、Prot 3.0/3.2/3.4、TS 11.5/12.5/13.5）
与代价参数（C_TEST=1，C_ERR=10/档，参考法误差=8%·SD）**全部是模拟的**
⇒ 论文只能表述为"**在模拟分档场景下的决策收益**"，
> **⚠️ 该表述已被 T3.1b 取代**：v3 改用真实按质论价（线性）、固定管理分档阈值与真实国标限值。
  不得表述为"在真实乳业中的收益"
```

### 修正记录

| 问题 | 修正 |
|---|---|
| oracle 按 `|ŷ−y|`（误差大小）排序，但代价按**档位错判**计算 | 改为按 `|grade(ŷ)−grade(y)|` 排序；修正后 oracle 从"被 plan 打败"变为真正的上界 |

**状态：✅ 已完成**

  - `validator` 可取 `Y`

  ```
  ① assess 取 Y → ContextViolation        ✅

  ③ report 取 Y → ContextViolation        ✅
  ④ validator 可取 Y                      ✅
  ⑤ 正常键可读（yhat/sigma 形状正确）      ✅

- **状态**：✅

  ⇒ 超时只保证"不阻塞编排"，不保证"资源立即释放"。文档与论文中须写明。

### T3.1b ⭐⭐ 路由升级：**损失函数无关**的规划器（v2 → v3）

**为什么要升级**：v2 的代价模型是"档位错判"（阶跃），阈值与代价参数**均为模拟**。
但真实按质论价是**线性**的（脂肪×单价 + 蛋白×单价），
而分档收购/合规判定才是阶跃的 —— 不同代价结构下最优策略不同。

**统一框架**
```
E[L_i] = ∫ L(ŷ_i, y) · p_i(y) dy      p_i(y): 由保形区间与 σ 构造
按 E[L_i] 降序复测 ⇒ 对任意损失函数 L 都是最优排序
```

**三种真实/半真实代价结构**
| 结构 | 来源 | 损失函数 |
|---|---|---|
| **linear** | ✅ 真实按质论价（[奶业协会](http://www.ce.cn/cysc/sp/info/201108/23/t20110823_21026053.shtml)） | `L = w·\|y−ŷ\|` |
| **grade** | 企业分级（**固定规划阈值**，与数据无关 ⇒ 无泄漏） | `L = 1[档位不同]` |
| **compliance** | ✅ 真实国标 GB 19645/25190 | `L = 10·1[y < 限值]`（不对称） |

**升级结果（自测 5 项全通过）**
```
linear      : plan 与 greedy_σ **完全相等（0.0%）** ⇒ 数学等价，无损
grade       : plan 优于 greedy_σ **+5.0% ~ +8.3%**
compliance  : Fat 优于 **+17.5% / +28.1%**
              ⚠️ Prot 为**空检验**（Prot 最小 2.99 > 国标 2.9 ⇒ 0/297 不达标）
```

**⭐⭐ 数据核查（重要发现）**
```
本数据是**研究级优质牛群**：
  蛋白 2.99–5.07（国标 2.9）⇒ 100% 达标
  非脂乳固体 8.53–11.11（国标 8.1）⇒ 100% 达标
  脂肪 1.71–7.70（国标 3.1）⇒ 94.3% 达标（17/297 不达标）
⇒ **合规判定情景只对 Fat 有意义**
⇒ 该系统的价值在**精细化定价**，而非合规筛查
```

**⚠️ 试过但未采纳的改进（均 <1.5%，在噪声内）**
```
· 距离代理（kNN 距离 / 马氏距离 / 局部密度比）预测 |error|
  corr：knnk +0.26 ｜ mahal +0.23 ｜ knn1 +0.10 ｜ margin −0.16
  而 σ 为 +0.28 ⇒ 距离代理**不如 σ**
· 元模型（σ + |ŷ| + 距离 → 岭回归预测 |error|）：线性损失下仅 +0.3~1.1%
⇒ **线性损失下 σ 排序已接近可达上限，剩余 11% 与 oracle 的差距是信息上限**
```

**状态：✅**

## P5r ✅ **核心论断的稳健性检验**（含第三次方向错误）

### 动机
    "σ 优于工业阈值邻近法 20–27%" 是目前最有说服力的论断，
    但有两个可被审稿人攻击的点：

| **B 随机基线稳定性** | random 抽 100 次取分布 | σ 落在分布之外，**P=0.99–1.00**；优于 random **+13.5% ~ +17.0%** |
| **C 预算点敏感性** | 5%/10%/20%/30%/50% 五个预算 | **σ 全部最低** |
| **D 指标一致性** | AURC vs 单点风险方向比对 | **3/3 一致** ✅ |

| 目标 | 预算 | σ | 阈值邻近 | random |
|---|---|---|---|---|
| Fat | 20% | **0.1196** | 0.1488 | 0.1378 |
| Prot | 20% | **0.0456** | 0.0512 | 0.0499 |
| TS | 20% | **0.1386** | 0.1635 | 0.1615 |

**⭐ σ 的风险随预算增大单调下降**（Fat 0.1257 → 0.1123）—— 行为正确。

### 🔴 第三次犯同一个方向错误

```
C 段写 `keep = order[k:]`
  order 是 suspicion **升序**（最不可疑在前）
  ⇒ order[k:] 丢掉最不可疑的，保留最可疑的 ⇒ 与 AURC 语义相反
  ⇒ 导致 "A 段说 σ 最好、C 段说 σ 最差" 的**自相矛盾**

⚠️ 这是本项目第 3 次同一类错误：
   ① 最初 AURC 算成"被拒样本"的平均误差
   ② （同上，同一处）
   ③ C 段 order 方向反了

修法：统一用 `order = argsort(-score)`（最可疑在前）+ `keep = order[k:]`，
     并加入 **D 一致性断言**（AURC 与单点风险必须方向一致）
```

### ⭐ 结论

```
"σ 优于阈值邻近 20–27%" 现在是**稳健论断**：
  · 不依赖我选的阈值（5 组全胜）
  · 不是单次抽样巧合（100 次，P=0.99–1.00）
  · 不依赖单一预算（5 个预算点全胜）
  · 两个指标互相印证
```

## P5t ⭐⭐⭐ **Guarded Agent**（LLM 提议 + Tool Use + 确定性门控）

> **动机**：为秋招"Agent 岗"补一个**真正的** Agent 环 —— 但不是为了简历加功能，
> 而是由本项目实测结果**推导出的必然架构**：
> LLM 单独决策准确率仅 46.7% ⇒ 不能直接决策；但也不该完全弃用。

### 架构
```
LLM 提议（tool use，最多 4 轮）
   │  可调 5 个只读工具：get_interval / get_grade / get_thresholds /
   │                      get_regret / get_status
   ▼
确定性门控 Guard（7 条规则，每条都可用阴性对照推翻）
   ├─ G1 action ∈ {report, retest, reference}
   ├─ G1b 必须覆盖所有目标
   ├─ G2 不可报告目标不得 report
   ├─ G3 整族缺失退化时不得 report
   ├─ G4 理由码 ⊆ CONCEPT_CODES
   ├─ G5 提议中的数值必须可溯源（白名单 = **工具能告诉 LLM 的全部量**）
   └─ G6 report 不得是期望损失最高的动作
   ▼
通过 ⇒ 采纳 LLM 决策；不通过 ⇒ **回退规则决策**
```

### 实测（12 样本，真实 LLM）
| 指标 | 结果 |
|---|---|
| 门控采纳率 | **12/12 = 100%** |
| 工具调用 | **平均 18 次/样本**（14–19）← 真 ReAct 循环 |
| 决策与规则一致 | 11/12 |
| 真实损失 Δ（LLM − 规则） | **−0.00208**（1 例更优，0 例更差） |

**⚠️ 决策增益**极小且不显著** —— 因为规则在给定信息下已接近最优。**

### 🔴 修掉一个真实的门控缺陷（由实测暴露）
```
第一版 G5 白名单只含 lo/hi/sigma/q，**漏了 width = hi - lo**
而 `get_interval` 工具明确返回 width
⇒ LLM 正确引用"区间宽度 0.62"反被判"不可溯源"
⇒ **门控 100% 拒绝 ⇒ 整个 Agent 退化为纯规则（空壳）**

⭐ 原则：**白名单 = 工具能告诉 LLM 的全部量**
   （LLM 只能知道工具说过的，工具说过的都必须允许）
```

### 🔴 还修掉一个成本尺度错误（更重要）
```
我把 regret 写成 `q·σ`
实测：区间半宽 = **q（绝对量，目标量纲）**，不是 q·σ
  Fat：q=0.312，半宽实测 0.3118 ⇒ 差 14 倍
```

### ⭐⭐ 新发现：**triage 是否有内容取决于成本比 ρ = c_test / E|err|**

| ρ | all_report | all_retest | rule(σ) | oracle | triage 有内容 |
|---|---|---|---|---|---|
| 0.01 | 104.04 | 1.04 | 44.12 | 1.04 | ❌ 退化 |
| 0.10 | 104.04 | 10.40 | 48.79 | 9.93 | ⚠️ |
| **0.20** | 104.04 | 20.81 | 53.97 | 18.99 | ✅ |
| **0.50** | 104.04 | 52.02 | 69.53 | 41.70 | ✅ |
| **2.00** | 104.04 | 208.08 | 147.30 | 89.05 | ✅ |

**⭐ triage 有内容的区间：ρ ∈ [0.20, 2.00]**

```
ρ < 0.20  ⇒ 复测太便宜 ⇒ "几乎全部复测"最优 ⇒ 三分类退化为单一策略
ρ > 2.00  ⇒ 复测太贵   ⇒ "几乎全部报告"最优 ⇒ 同样退化

⇒ 论文必须报告实验室实际的 ρ，并说明落在哪个区间
   （此前用 c_test = 0.03×sd，对应 ρ≈0.24，勉强在区间内）
```

**状态：✅**

## P5u ⭐⭐ G7 预算门控 + Guarded Agent 接入 pipeline

## P5v ⭐⭐⭐ **升级为真多 Agent 系统**（agent-as-tool + 审议环）

> **触发**：用户问"这是多 Agent 系统吗"。审计结论：**不是** ——
> 只有 1 个 Agent 有自主性、**无 Agent 间通信**、中心化编排、无协商。
> ⇒ 按 MAS 五条判据逐条升级。

### 升级内容

**① agent-as-tool（能力边界不同的两个 Agent）**
```
A5b 决策 Agent  ⇄  A1 感知 Agent

   A1 **能看光谱但不能决策**
   ⇒ 必须通过 `request_spectral_recheck` **跨 Agent 请求**
```
**这就是真交互：不是查数据，而是请求另一个 Agent 做事。**

**② 审议环（proposer–critic，多轮）**
```
A5b 提议 → V 审计 Agent **质疑**（带可执行建议）→ A5b **修订** → 再审
最多 3 轮；仍不通过 ⇒ 回退规则
```

### 实测（真实 LLM）

**A. 正常样本（8 个）**
| 指标 | 结果 |
|---|---|
| **A1 被调用** | **2/8** ✅ agent-as-tool 真实发生 |
| 修订次数 | 0/8（LLM 首轮即合规） |
| 工具调用 | 平均 **19.5 次**/样本 |

**B. 刻意构造的触发场景（证明审议环能工作）**

| 场景 | 结果 |
|---|---|
| **S1 整族缺失去退化** | round 1 违规 `G3 退化状态下不得 report` ⇒ **round 2 修订后通过**（2/2 次） |

### ⭐ 结论

```
✅ **这是真多 Agent 交互**：
   · Agent 间消息往返（提议/质疑/修订，多轮）
   · 能力边界不同（A5b 看不到光谱，必须请 A1）
   · 质疑**确实改变**了决策（S1/S3 实测）

⚠️ 但正常样本下审议环很少触发（LLM 首轮通常合规）

## 关键决策记录

| 议题 | 结论 | 依据 |
|---|---|---|
| 并行粒度 | **分支级（5 Agent）为主，样本级为辅** | 分支计算特性不同、天然独立；且退化表可量化容错 |
| 多 Agent 通信 | 只保留"采集 ⇄ 路由"的重采协商 | 其余是 DAG，自由对话会被质疑必要性 |
| 上下文隔离 | 真值只在 validator 可见 | 否则第四章可靠性结论有泄漏 |
| 降级阈值 | 三档（0.0010 / 0.0025） | 实测 drop-one 退化表 |
| 路由智能 | 区分"已通过 / 可修 / 无望" | 规划与规则的分界线 |
| **路由的规划信号** | **期望档位误差（v2，常数区间切片）** | v2 ≈ 信息论最优（Prot/TS 与 homo_opt 完全相同）；σ 类改进全部无效 |
| **路由的上界对照** | **同方差最优（homo_opt）**，不是 oracle | oracle 需知真值，不可实现；其差距是不可约成本 |
| **规划成立的前提** | 决策必须有阈值 | 无阈值时规划退化为"按 σ 排序"，无优势 |
