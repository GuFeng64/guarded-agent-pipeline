> 与模型开发的 `SKILL.md`（规则 A–CG）平行的一套规则。
> **触发条件**：任何涉及 `revision/agent_system/` 的设计、实现、评估、修改。
> **本文件的每一条都对应一个已发生或可预见的错误。**

## 零、根本定位（不可动摇）

### 规则 Z1：**基础设施不是科学贡献**

```
调度器、上下文隔离、DAG 执行、失败重试、结果合并 —— 这些是工程
⇒ 论文里的贡献必须落在**算法/决策/机制**上，不能是"我们实现了并行调度"
✅ 可写：分支级并行的多 Agent 推理架构 + 基于实测退化量的降级容错
❌ 不可写：我们设计了一个 6 Agent 的调度框架
```

### 规则 Z2：**"Agent"这个词必须有代价**

```
本项目自查结论（5/6 是函数）：
  ① 采集检查 = 阈值判断        ② 预测 = 调用模型
  ③ 评估 = 查表                ④ 路由 = if/else
  ⑥ 回流 = 打标签
⇒ 把函数叫 Agent，答辩会被直接质疑

强制：一个组件只有在满足**至少一项**时才可称为 Agent：
  · 有控制回路（失败 → 改变状态 → 重做）
  · 有规划（在约束下做组合选择，而非单条规则）
  · 有工具调用（真的调用外部系统并据结果决策）
  · 有记忆（跨轮次状态影响后续决策）
⭐ 否则一律称为"阶段（stage）/ 规则（rule）"，并在文档中照实写。
```

### 规则 Z3：**数值链路中不得出现 LLM**

```
所有数值、区间、分级、路由决策必须由确定性代码产生
⇒ LLM 只能出现在**报告表述**环节，且不得修改任何数值
⭐ 理由：质量控制要求可复现、可审计；LLM 的非确定性会破坏保形区间的覆盖率保证
```


### 规则 Z4：**先验证风险最高的核心假设，再建基础设施（fail-fast）**（2026-11-16）

```
本项目反例：初版任务流程把 P0（基础设施：隔离 + 并行调度）排在最前，
            把真正决定成败的 P3（路由规划）排在第三。
⇒ 若规划不成立，前面几小时的基础设施投入全部作废

强制：任务排序按"**证伪代价 × 失败概率**"降序，而不是按依赖顺序。
⭐ 若某核心假设可以**不依赖基础设施**单独验证（如用缓存预测），必须最先做。
```

### 规则 F1：**Oracle 基线必须与代价/指标的定义一致**（2026-11-16）

```
本项目 bug：代价按"**档位错判数**"计算，
            但 oracle 按 `|ŷ − y|`（误差大小）排序
⇒ oracle 被自造的 plan 策略"打败"（plan 89 vs oracle 189），
  暴露出 oracle 不是真正的上界

正确：oracle 必须按**与评估指标相同口径**的不可实现真值排序
    （按 `|grade(ŷ) − grade(y)|` 排序后，oracle 恢复为上界）

⭐ 自查信号：**任何策略"打败了 oracle"，一定是 oracle 写错了**，不是策略创新。
```

### 规则 F2：**所有模拟假设必须显式标注，并隔离在结论表述之外**（2026-11-16）

```
本项目使用了模拟量：
   决策阈值（Fat 3.0/3.5/4.0/4.5 等）
   代价参数（C_TEST=1、C_ERR=10/档）
   参考法误差（8%·SD）
⇒ 全部来自假设，**不是实测**

强制：
  ① 代码里以常量集中定义并注释"模拟"
  ② 日志与文档中显式标注"模拟场景"
  ③ 论文只能写"在模拟分档场景下的决策收益"，
     不得写"证明了在真实乳业中的收益"
```

### 规则 F3：**"排序难度"与"排序代价"是两件事**（2026-11-16）

```
本项目实测：按 σ 排序复测（greedy_s）在 Prot 20% 预算下
            比随机更差（139 vs 129）

⇒ σ 度量的是"预测有多不确定"，不是"错判会有多贵"
⭐ 涉及决策/成本的问题，必须用**代价口径**的信号（如期望档位误差），
  不能直接沿用不确定性排序。
```


### 规则 F4：**上界必须"可实现"，"知情 oracle"只作参考不作判据**（2026-11-16）

```
本项目教训：
  oracle 按**真实档位错误**排序（需知真值）⇒ Fat 20% 预算代价 = K·C_TEST
  ⇒ 它把所有错误样本都修好了 ⇒ 离现实太远，无法判断启发式好坏
  ⇒ 一度误判为"我们的启发式差 5 倍，需要继续改进"

正确做法：定义**可实现上界**——在"允许使用的信息"范围内能做到的最好
  本项目：仅知 ŷ 与全局误差尺度 ⇒ 同方差最优（解析可算）
⭐ 判据变成"启发式 vs 可实现上界"：
   Prot/TS 完全相同 ⇒ 已最优；Fat ±5% ⇒ 可接受
⇒ 若某启发式已贴近可实现上界，**停止迭代**，把剩余差距表述为不可约成本
```

### 规则 F5：**当改进尝试反复无效时，先检查"信息是否存在"，而不是继续换算法**（2026-11-16）

```
本项目：路由规划 v3（σ 调制宽度）/ v4（高斯近似）/ v5（混合权重）
        全部无一致改善
根因：误差**近似同方差**（模型侧已实测：σ 归一化使区间宽 16–23%）
⇒ σ 对"该样本误差多大"没有额外信息 ⇒ 任何用它改进代价推理的尝试都注定失败

强制：连续两个改进版本无效时，停下来问：
  ① 我引入的信号是否真的对该目标有信息？（先算相关/条件分布）
  ② 是否已有实测结论说明该信息不存在？（查两侧记录）
⭐ 信息不存在时，正确结论是"已达上界"，不是"再换个算法试试"。
```

### 规则 F6：**"与不可实现上界的差距"必须重新审定为"不可约成本"再写入结论**（2026-11-16）

```
Fat：v2 299 vs oracle 59（20% 预算）⇒ 早期误读为"差 5 倍，启发式不行"
修正后：v2 299 vs homo_opt 289 ⇒ 实际只差 3.5%
⇒ 与 oracle 的 5 倍差距 = **不可约的"不知道真值"成本**

强制：凡报告"与 oracle 的差距"，必须同时给出"与可实现上界的差距"，
      并在文字中明确二者语义不同。
```

## 一、上下文与数据纪律

### 规则 A1：**真值只在校验器中可见**

```
Agent 可见输入白名单：
  采集 Agent  ← 原始谱
  分支 Agents ← 各自视图 + 各自模型
  汇总 Agent  ← 各分支输出
  评估 Agent  ← ŷ + σ（不含真值）
  路由 Agent  ← 区间 + 容许限（不含真值）
  报告 Agent  ← 路由决策（不含真值）
  校验器      ← 报告 + 真值   ← **唯一**

🔴 违反后果：第四章的"可靠性评估"不再是盲的，全部结论作废
强制：每个 Agent 的输入必须由 `context.py` 显式白名单提供，
      禁止直接访问全局数据对象。
```

### 规则 A2：**校准数据只能来自训练/校准集，不能来自测试集**

```
σ 的逐分支仿射、保形分位数 q、路由阈值 τ 都在**训练/校准行**上估计
⭐ 拒识后校准集变了 ⇒ 必须在**存活的校准样本**上重新取分位数
   （已实测：不重新校准会导致覆盖率保证失效）
```

### 规则 A3：**任何"按分数加权/收缩/选择"必须先验证该分数与目标的关系**

```
沿用模型章程规则 BY：
  ① 先算 corr(分数, |残差|) + 置换检验
  ② 前提显著再做；不显著直接报告"该分数不预测难度"
⭐ 本项目已验：σ 与 |残差| corr +0.34（有效）；scatter +0.14（排序反而差于随机）
```


### 规则 A4：**"需要真值"的组件往往只需"已确认的标签"，不需要真值本身**（2026-11-16）

```
本项目实例：回流 Agent 最初需要 reference_values（真值）来标记高价值样本
⇒ 违反规则 A1（真值只在 validator 可见）
⭐ 正确做法：由 validator 完成"是否被参考法确认"的判断，
   只把**确认过的样本 ID** 传给回流 Agent
⇒ 回流 Agent 仍然完成原职能，但不再接触任何真值

强制：设计任何"需要真值"的环节时，先问：
  "它是需要**真值本身**，还是只需要一个**由可信环节预先算好的结论/标签**？"
  ⇒ 优先后者，把真值访问收敛到 validator 一处。
```

### 规则 C5：**每个模块必须带可执行自测，且自测要包含"配置一致性检查"**（2026-11-16）

```
本项目 `context.py` 的 8 项自测中，第 ⑧ 项是**白名单配置自检**：
  遍历 AGENT_ACCESS，断言除 validator 外没有任何 Agent 被允许访问真值键
⇒ 该项立刻抓出 feedback 的越权配置

强制：自测不只测"功能对不对"，还要测"**声明与实际是否一致**"：
  · 配置类模块：断言配置满足不变量（如"只有 validator 能看真值"）
  · 数据类模块：断言形状/范围/单调性（如"区间 lo ≤ hi"）
⭐ 这类断言成本极低，但能抓住人工审查漏掉的配置错误。


### 规则 C6：**并行的确定性来自"归并规则"，不是来自"执行顺序"**（2026-11-16）

```
本项目做法：先全部 submit（并发执行），再**按 CANONICAL_BRANCHES 顺序**逐个取结果
⇒ 结果张量的列顺序与"谁先算完"无关
⭐ 若按完成顺序 append，同一份代码在不同负载下会得到不同列序，
   进而使融合权重与列的对应关系错位 —— 这类 bug 极难复现

强制：任何并发归并都必须有**显式的规范顺序常量**，并写进自测的判据
（本项目判据②：「归并顺序 = 规范顺序」）。
```

### 规则 C7：**超时的语义必须如实写明——它只保证"不阻塞"，不保证"释放资源"**（2026-11-16）

```
Python 线程无法强杀；Future.cancel() 对已运行任务无效
⇒ 超时的真实语义是"编排不被卡死"，而非"计算被终止"

强制：① 代码注释与文档中写明该限制
      ② 论文中不得把"超时机制"表述为"资源回收"或"任务中止"
      ③ 若确需真正中止，必须换成进程隔离（另立任务，不得混淆）
```

## 二、组件设计纪律

### 规则 B1：**降级/容错阈值必须来自实测，不是猜**

```
本项目实测 drop-one 退化表：
  b9 +0.0006 ｜ b1 +0.0014 ｜ CNN +0.0014 ｜ b7 +0.0015 ｜ b8 +0.0022
  整个 TabPFN 族 +0.0258（不可降级）
⇒ 降级规则的三档阈值（≤0.0010 / 0.0010–0.0025 / >0.0025）由此而来
强制：任何"重试几次""超时多少秒""降级还是报错"的决策，
      必须能指向一个实测数字或明确标注为"待实测的经验值"。
```

### 规则 B2：**任何"智能"组件必须有至少三个对比基线**

```
路由规划：random / 贪心按 σ / Agent 规划 / Oracle（四选）
   ⭐ 缺 Oracle 就不知道离上界还有多远；缺 random 就不知道是不是"少测就好"
拒识规则：σ / |f| / scatter / random（已做）
⭐ 只有跑赢全部基线，才能说"这个组件有价值"
```

### 规则 B3：**对照必须被证明真的与处理组不同**

```
沿用模型章程规则 CB：
某次"随机拒识"对照用 rng.permutation(值) 再取分位数
⇒ 分位数与顺序无关 ⇒ 与 σ 拒识**完全相同**（结果一模一样）
强制：跑完先断言 `not np.allclose(treatment, control)`
⭐ 若两组结果完全相同，第一反应是"对照写错了"
```

### 规则 B4：**区间/覆盖率类比较必须在匹配的实测覆盖率处进行**

```
沿用模型章程规则 CC：在相同**名义**覆盖率下比宽度是不公平的
（σ-norm 实测 90.9% vs 常数 90.6%）
强制：扫多档名义覆盖率 → (实测覆盖率, 宽度) 曲线 → 共同覆盖率处插值比较
```

## 三、工程实现纪律

### 规则 C1：**每一步只做最小改动，且必须能独立验证**

```
一次只改一个组件；每个组件完成后立刻跑它的单元检查
⭐ 禁止"先全部写完再一起调"
判据：每个 Agent 必须有一个可独立运行的 `__main__` 自测入口
```

### 规则 C2：**并行与确定性必须分离**

```
并行：分支级（5 个 Agent 并发）+ 样本级
确定性：给定输入，每个分支的输出必须可复现
⇒ 并行不得引入非确定性（结果按固定顺序归并，不得依赖完成顺序）
强制：归并时按分支 ID 排序，不按完成时间排序
```

### 规则 C3：**超时/异常必须被显式处理，禁止静默降级**

```
每个分支 Agent 调用必须带超时；失败必须返回**结构化的失败原因**
⭐ 降级必须在输出中显式标注（degraded=True + 缺失了谁），
   不允许"看起来正常但其实少了一个分支"
```

### 规则 C4：**Windows PowerShell 下禁止用内联 here-string 写多行 Python**

```
沿用模型章程规则 BV：三引号会被 PowerShell 破坏
⇒ 一切超过 3 行的 Python 补丁，用 write 工具写成 .py 文件再执行
```

### 规则 D2：**每完成一步，必须同时更新三件事**

```
① AGENT_TASKS.md 的进度表（状态 + 实际结果）
② 若发现设计缺陷 ⇒ 更新 AGENT_SYSTEM.md，并在 TASKS 里记录变更原因
③ 若发现新的错误模式 ⇒ 更新本文件（新增规则）
⭐ 只更新代码不更新文档 = 未完成
```

### 规则 D3：**每步结束前必须自查"设计与代码是否有缺陷"**

```
固定五问：
  ① 我这次的实现，与已写下的设计是否一致？不一致是有意还是疏漏？
  ② 有没有引入"样本相关"的机制？（已验证全部失败，见模型章程规则 BT）
  ③ 对照实验是否被证明真的不同？（规则 B3）
  ④ 是否在比较前统一了口径（覆盖率、划分、噪声）？（规则 B4）
  ⑤ 有没有用"看起来有改善"掩盖"效应在噪声内"？
⭐ 五问有任何一项存疑，不得标记该步为"完成"
```

### 规则 D4：**进度状态只允许四种取值**

```
⬜ 未开始   🔄 进行中   ✅ 已完成（有结果且通过判据）   ⛔ 阻塞（写明原因）
⭐ 禁止使用"基本完成""大概可以"这类模糊状态
```

## 五、与模型侧的关系

### 规则 E1：**Agent 系统只能消费模型侧的定稿产物，不得反过来改模型**

```
消费：models_final/v39/ 的配置与 OOF 预测、experiments/ 的缓存
禁止：为实现某个 Agent 功能去改动 v39 的结构或重新调参
⭐ 若确实需要模型侧配合（如增加一种输出），必须先记录到模型记录并单独验证
```

### 规则 E2：**Agent 侧的发现若涉及模型结论，必须回流到模型记录**

```
例：若发现"某个分支在某类样本上系统性失效"，这属于模型认知 ⇒ 写入模型记录
⭐ 两侧记录不混写，但结论要互通
```

### 规则 E3：**接入既有模型产物时，必须先用“逐元素对拍”确认语义，再谈功能**（2026-11-16）

`
本项目两次 bug 都是**语义误判**，不是逻辑错误：
  ① 单位误判：缓存已是归一化空间，我当成原始单位 ⇒ 双重归一化
  ② 折结构误判：融合用的是**每折的内层训练预测**，
     不是“全局 OOF 在训练行上的值”（后者来自别的折的模型）

⇒ 两者都表现为“代码跑通、形状正确、结果错”，极难靠肉眼发现

强制：接入任何既有产物（缓存/模型输出/中间结果）时，第一步做三件事：
  ① **逐元素对拍**：用原有代码重算一遍，np.allclose(new, old, atol=1e-10)
  ② **写清单位**：原始 / 标准化 / 归一化，并在断言中体现
  ③ **写清折语义**：哪个数组来自哪一折的哪个模型
⭐ 对拍通过之前，不得在该产物上叠加任何新功能。
`

### 规则 E4：**“形状对、数值错”只能靠数值锚点抓出来**（2026-11-16）

`
本项目在自测里写死了两个**数值锚点**：
  等权融合 gap = 0.0329（不含 TS 闭合）
  v39 定稿     gap = 0.0324（含 TS 闭合）
⇒ 一旦语义误判，锚点立刻失败，而不是等到下游指标异常

强制：每个接入模型的模块，自测中必须断言至少一个**已知数值锚点**，
      且锚点要写明“是否包含某个后处理”，避免把两个不同的量当成一个。
`

### 规则 B5：**"查表决策"必须用真实数据回归验证表本身**（2026-11-16）

```

### 规则 B10：**归一化指标不得用被检测对象自身估计尺度**（2026-11-16）

```

   ⇒ 实测"3 个尖峰比 8 个更严重"，跨情形完全不可比
```

### 规则 C31：**任何"证书/断言/证据"都必须有阴性对照**（2026-11-16）

```
本项目最严重的一次假证据：

  阴性对照（故意在模块级加载 Y 的探针）证实：证书报 False，而探针确实有 Y

⇒ 该证书在**所有情况下**都通过，因此**什么也没证明**。

强制：每条"保证性证据"必须配一个**应当失败的用例**——
  ① 构造一个**故意违反**该保证的输入
  ② 断言证据会因此**失败**
⭐ 若无法构造出使该证据失败的情形，说明它不具区分力，不得写入结论。
```

### 规则 C32：**进程隔离 ≠ 文件系统隔离，不得混称"物理隔离"**（2026-11-16）

```
本项目错误表述："子进程物理上无法访问真值"
实测：阴性对照的 worker 在模块级 `np.load(磁盘文件)` **成功**拿到了 Y (297,5)
⇒ 进程隔离只隔离**内存与载荷**，不隔离**文件系统**

强制表述分层：
  · **载荷隔离**：父进程只发送白名单字段（可断言）       ← 本项目做到
  · **代码隔离**：worker 代码不加载数据（可检查）        ← 本项目做到
  · **文件系统隔离**：worker 无法读取数据文件（需容器/权限）← 本项目**未做**
⭐ 不得把前两者说成"物理上无法访问"。
```

### 规则 C34：**"防篡改"必须覆盖**文本**，不能只覆盖结构化数据**（2026-11-16）

### 规则 C39：**极小样本的比例估计不得用来下定性判断**（2026-11-16）

```

  ⇒ 据此判定"LLM 的理由基本是事后合理化"（一个**定性结论**）
  扩样到 27/124 = 21.8% ⇒ **结论方向都变了**
  而 1/29 的 Clopper–Pearson 95% 区间是 **0.1%–17.8%**，
  原始数据**从一开始就不支持**那个定性判断

强制：比例型结果（准确率/一致性/翻转率）必须：
  ① 报告「点估计 (n, 95% CI)」
  ② **CI 下界与上界跨越"结论阈值"时，不得下定性结论**
     （如 CFS 判定线 30%：区间 15–30% 跨越它 ⇒ 只能说"可能偏低"）
  ③ n < 30 的比例估计只能作为**探索性观察**，不得写入结论
```

```
本项目：6 → 25 样本，成本 424 次调用 / 107k tokens / 约 7 分钟
收益：CI 宽度从 ±21pp 收窄到 ±11pp，且**推翻了一个错误结论**

⭐ 判据：若某结论的 CI 宽度 > ±15pp，且扩样成本可接受（< 1 小时 / < $1），
```

### 规则 C41：**排序类指标必须验证"方向"——oracle 必须最优**（2026-11-16）

```
本项目错误：AURC 算成了"被拒样本的平均误差"
  ⇒ oracle（按真误差排序）0.2891 > random 0.1387 —— 数学上不可能
  ⇒ 说明指标方向反了

强制：任何"越小越好/越大越好"的排序类指标，必须内置**自洽性断言**：
  ① 用**真值排序（oracle）** 计算该指标
  ② 断言 oracle 一定是**最优**（AURC 最小 / AUC 最大）
  ③ 若不满足 ⇒ 实现有错，不得使用
⭐ 这条断言是**零成本的**，但能立刻暴露方向错误。
```

### 规则 C42：**"重合率低"不等于"互补"，组合收益必须实测**（2026-11-16）

```
本项目假设：σ 与阈值邻近在 20% 预算下重合率仅 10–19%
            ⇒ 推断"两者互补，组合应更好"
实测：**9 种组合信号全部比 σ 单独更差**（平均 −3% 到 −32%）

原因：阈值邻近本身是更弱的信号（AURC 差 20–36%），
     与更弱信号低重合只是"两者关注不同噪声"，不构成互补。

强制：判断两个信号是否互补，必须：
  ① **实测组合后的指标**，不能从重合率/相关性推断
  ② 同时报告两个信号**单独**的指标（确认弱者确实弱）
⭐ 判据：若弱信号单独比强信号差 >10%，组合前先预期"大概率无收益"。
```

### 规则 C43：**排序方向必须写成"具名变量"，禁止裸用 argsort 结果**（2026-11-16）

```
本项目**三次**在同一类错误上翻车：
  ① AURC 算成"被拒样本"的平均误差（应为"保留样本"）
  ② 同处修正不彻底
  ③ 预算点风险写 `keep = order[k:]`，而 order 是**升序**
     ⇒ 丢掉了最不可疑的，与 AURC 语义相反 ⇒ 两个指标自相矛盾

根因：`np.argsort(score)` 的方向**不在代码里显式表达**，
      读者（包括我自己）无法一眼看出"前 k 个"是可疑还是不可疑。

强制写法：
    worse_first = np.argsort(-score)     # ⭐ 名字说明方向
    reject = worse_first[:k]             # 前 k 个 = 最可疑 ⇒ 被拒
    keep   = worse_first[k:]             # 其余 = 保留

⭐ 并配一个**跨指标一致性断言**：同一数据上，
   积分型指标（AURC）与单点指标（某预算的风险）必须方向一致。
   ≥3 次同类错误说明这不是偶然，必须在写法层面消除。
```

### 规则 C44：**指标的"期望值"必须能解析推导，不能凭直觉**（2026-11-16）

```
本项目第 4 次方向错误：
  自检里把 AURC 的期望值写成 2.0 / 4.0 —— 那是"**风险的简单平均**"
  而 AURC 是"对覆盖率**积分**" ⇒ 正确值是 1.60 / 3.20
  并且把"预算增大时风险应上升"写反（实际应下降）

⭐ 教训：连"我要检验的那个值应该是多少"都凭直觉 ⇒ 自检本身失效。

强制：为指标设期望值时，必须**手算一遍小样例**并写出推导过程：
  err=[1,2,3,4,5] → risk=[1,1.5,2,2.5,3] → cov=[.2,...,1]
  AURC = 0.2×(1.25+1.75+2.25+2.75) = 1.60
⭐ 若无法手算，说明该指标尚未真正理解，不得用于验证。
```

### 规则 C45：**门控的白名单必须覆盖"工具能返回的全部字段"**（2026-11-16）

```
本项目事故：G5（数值溯源）白名单只含 lo/hi/sigma/q，**漏了 width=hi−lo**
  而 `get_interval` 工具明确返回 width
  ⇒ LLM 正确引用"区间宽度 0.62"反被判"不可溯源"
  ⇒ **门控 100% 拒绝 ⇒ 整个 Agent 退化为纯规则（空壳），却"看起来在运行"**

⭐ 原则：**LLM 只能知道工具说过的数；工具说过的都必须允许。**
强制：白名单从**工具返回值遍历生成**，不手写字段清单。
```

### 规则 C46：**"决策有内容"需要先证明——成本比决定问题是否退化**（2026-11-16）

```
本项目发现：triage（报告/复测/参考）是否有内容，取决于
  ρ = c_test / E|err|
  ρ < 0.20 ⇒ 复测太便宜 ⇒ "几乎全复测"最优 ⇒ 三分类退化为单一策略
  ρ > 2.00 ⇒ 复测太贵   ⇒ "几乎全报告"最优 ⇒ 同样退化
  ⇒ **有内容的区间：ρ ∈ [0.20, 2.00]**

若在论文中报告"决策层的价值"，必须：
  ① 给出 ρ 的取值与来源（实验室实测成本）
  ② 证明 ρ 落在**非退化区间**内
  ③ 同时报告两种固定策略（全报告/全复测）的代价作为对照
⭐ 否则"决策优化"可能优化了一个退化问题。
```

### 规则 C47：**逐条合法的提议集合，整体仍可能不可执行**（2026-11-16）

```
本项目矛盾：
  Guarded Agent 是**逐样本**决策，每条提议都通过 G1–G6（合法）
  但若 10 个样本全说"复测"，而预算是 2 个
  ⇒ 这个**提议集合整体不可执行**（预算被击穿）

⭐ 逐条校验（local validity）≠ 整体可行性（global feasibility）。

强制：当决策受**全局约束**（预算、配额、总量）时，
必须再加一层**批量级门控**，并明确：
  ① 冲突时如何裁剪（本项目：按期望损失降序保留）
  ② 被裁剪的样本如何处理（本项目：回退规则）
```

### 规则 C48：**"多 Agent"必须按 MAS 判据自证，不能凭模块数量**（2026-11-16）

```
本项目审计：有 A1–A7 七个"Agent"命名的模块，但**不是**多 Agent 系统：
  ① 多个自主 Agent      —— 只有 1 个（LLM 决策）有自主性
  ② Agent 间通信        —— 无（orchestrator 按固定 DAG 顺序调用）
  ③ 协商/协调           —— 无
  ④ 去中心化控制        —— 中心编排器
  ⑤ 涌现行为            —— 无

强制：声称"多 Agent"前，逐条给出证据：
  · 哪个 Agent 有自主性？几个？
  · Agent 之间**实际发生过什么消息**？（要有日志/计数）
  · **质疑是否真的改变了决策**？（要有前后对比）
⭐ 仅"有多个模块并叫 Agent"不构成多 Agent 系统。
```
