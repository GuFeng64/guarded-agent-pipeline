# 门控案例

```bash
python examples/show_cases.py
```

五个"提议被拦下"和一个"修订后通过"的完整轨迹。
为了让对方一眼看懂门控在拦什么，这里直接贴运行输出。

---

## 基准：一个合法提议

```
提议动作：{"Fat": "report", "Prot": "report", "Lact": "reference",
          "TS": "report", "Urea": "reference"}
门控结果：通过
```

---

## C1 · G1 非法动作

```
提议动作：{"Fat": "ship_it", ...}
门控结果：拒绝
  ▸ G1 非法动作：{'Fat': 'ship_it'}
失败规则：['G1_valid_action']
→ 最终决策：回退规则
```

---

## C2 · G2 不可报告目标

```
提议动作：{"Lact": "report", ...}
门控结果：拒绝
  ▸ G2 不可报告目标被要求 report：['Lact']
失败规则：['G2_no_report_nonreportable']
→ 回退规则；Lact 的 RPD=1.59 ⇒ 只能 reference
```

---

## C3 · G5 编造数值

```
提议原文：Fat 区间宽度 0.3995，σ=0.1004，预计误差约 0.8765，可报告
门控结果：拒绝
  ▸ G5 数值不可溯源：['0.8765']
失败规则：['G5_numbers_traceable']
```

`0.3995` 和 `0.1004` 都由工具返回（区间与 σ），可以溯源。
`0.8765` 没有任何工具返回过 —— 它是模型编的，因此被拒。

**这一条是 G5 存在的全部理由：只校验"该有的在不在"不够，还要校验"不该有的在不在"。**

---

## C4 · G6 report 是最差动作

```
期望损失（Fat）：report 9.00 ｜ retest 1.00 ｜ reference 2.00
提议动作：{"Fat": "report", ...}
门控结果：拒绝
  ▸ G6 report 是期望损失最高的动作：['Fat']
失败规则：['G6_not_worst_action']
→ 回退规则 → Fat 改为 retest
```

---

## C5 · G7 批量预算击穿

```
[G7] 预算 2/10 ｜ LLM 提议复测 10 ⇒ 超预算，裁剪
→ 最终：retest 2 个 ｜ 回退规则 8 个
```

10 条提议**逐条**都通过 G1–G6，但合起来把预算击穿了。
G7 按期望损失降序保留预算内的 2 个，其余回退规则。

**逐样本门控管不了这件事：单条合法与整批可行是两个不同的判断。**

---

## C6 · 审议环

```
【第 1 轮】提议动作：{"Lact": "report", ...}
【审计 Agent】ok=False
  质疑：Lact 与 Urea 不可报告，只能 reference

【第 2 轮】提议动作：{"Lact": "reference", ...}
【审计 Agent】ok=True  ⇒ 收敛，采纳
```

审计 Agent 给的不是"拒绝"，而是**可执行的修订建议**。
提议方据此修订后重审通过。

---

## 六个案例的分布

| 案例 | 触发层 | 结果 |
|---|---|---|
| 基准 | — | 通过 |
| C1 | 逐样本 G1 | 回退规则 |
| C2 | 逐样本 G2 | 回退规则 |
| C3 | 逐样本 G5 | 回退规则 |
| C4 | 逐样本 G6 | 回退规则 |
| **C5** | **批量 G7** | **裁剪 8/10** |
| C6 | 审议环 | 修订后采纳 |

四类逐样本违规、一类批量违规、一类经修订收敛。
